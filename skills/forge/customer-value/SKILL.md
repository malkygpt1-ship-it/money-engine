# Customer Value

## Before production

Write a one-sentence customer job: `When ___, I want ___, so I can ___.`

Define:
- target buyer;
- painful or costly current method;
- measurable improvement the product provides;
- frequency of use;
- what is reusable versus one-off;
- what the buyer receives that a generic article or chat answer does not provide.

## Value test

A paid product should normally provide at least three of:
- working calculations or automation;
- reusable templates;
- examples or sample data;
- decision support;
- error prevention;
- saved setup time;
- structured workflow;
- visual summary/dashboard;
- editable source file;
- concise instructions embedded in the artifact;
- repeat monthly/weekly/project use.

## Price sanity

For low-ticket products, the buyer should be able to understand the value within 60 seconds and get a useful result within 10 minutes.

If the output is predominantly prose, ask whether a free article would satisfy the same job. If yes, improve the deliverable or reject the paid-product concept.

## Release evidence

Store a short `value_case` with the product brief containing buyer, job, concrete utility, repeatability and price rationale.
